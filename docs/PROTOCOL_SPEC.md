# Спецификация протокола ShadowStar (SSP)

**ShadowStar Protocol (SSP)** — это высокопроизводительный антицензурный протокол нового поколения на базе архитектуры Shadowsocks, спроектированный специально для обхода современных систем глубокой инспекции пакетов (DPI, ТСПУ РКН, GFW) и активного зондирования (Active Probing).

---

## 1. Проблема: почему классический Shadowsocks блокируется

1. **Энтропийный анализ первого пакета (Shannon Entropy Detection)**:
   Оригинальный Shadowsocks и AEAD 2022 передают зашифрованные байты прямо с нулевого смещения TCP-потока. DPI вычисляет энтропию ($H > 7.6$). Если поток на порту 443 не содержит валидного TLS-рукопожатия, он блокируется или сбрасывается TCP RST.
2. **Анализ длин пакетов (Packet Length Fingerprinting)**:
   Размеры начальных кадров в традиционных протоколах жестко коррелируют с внутренними заголовками. Нейросетевые классификаторы DPI определяют профиль прокси по распределению длин первых 4–8 пакетов.
3. **Активное зондирование (Active Probing)**:
   При обнаружении подозрительного трафика сканеры цензора отправляют на подозрительный IP:порт кастомные пробы (TLS ClientHello, случайные байты, HTTP GET). Сервер, который сбрасывает соединение или молчит по таймауту, мгновенно вносится в черный список.
4. **Блокировка по SNI**:
   Фильтрация по имени хоста в незашифрованном поле `server_name` ClientHello.

## 3. Детальное описание механизмов

### 3.1. TLS 1.3 Reality Camouflage
Клиент формирует корректный пакет TLS 1.3 ClientHello:
- **Record Layer**: `0x16 0x03 0x01` (Handshake).
- **Handshake Type**: `0x01` (ClientHello).
- **SessionID**: 32 байта, содержащие метку времени, соль и HMAC-токен.
- **Extensions**:
  - `server_name` (SNI) — доверенный популярный домен (по умолчанию `www.microsoft.com`).
  - `supported_versions` — TLS 1.3 (`0x0304`).
  - `key_share` — эфемерный публичный ключ клиента X25519.
  - `padding` — динамическое заполнение от 16 до 128 байт.

### 3.2. TCP Chunker (Фрагментация на клиенте)
Для обхода аппаратных комплексов ТСПУ (которые анализируют первый сегмент TCP):
- Пакет ClientHello разбивается на 2 сегмента TCP (первые 24 байта и остаток).
- Между отправкой сегментов вставляется микрозадержка (1–2 мс).
- DPI ТСПУ не находит SNI в первом сегменте и пропускает поток, в то время как целевой сервер прозрачно склеивает поток на уровне ядра TCP.

### 3.3. Эфемерный обмен ключами (Forward Secrecy)
- Клиент и сервер генерируют одноразовые пары ключей Curve25519 (X25519).
- Вычисляется общий секрет: `SharedSecret = ECDH(PrivKey, PeerPubKey)`.
- С помощью **HKDF-SHA256** выводятся 4 независимых ключа:
  - `ClientKey` (32 байта) + `ClientIV` (12 байт) — для направления Клиент $\to$ Сервер.
  - `ServerKey` (32 байта) + `ServerIV` (12 байт) — для направления Сервер $\to$ Клиент.
- Даже при будущей компрометации мастер-ключа прошлый записанный трафик невозможно расшифровать.

### 3.4. Кадрирование и морфинг пакетов (Anti-Fingerprinting)
Каждый кадр данных туннеля шифруется независимым AEAD шифром:
```
+-------------------------------------------------------------+
| Зашифрованная длина тела (2 байта) + AEAD Tag (16 байт)     |
+-------------------------------------------------------------+
| Зашифрованное тело кадра:                                   |
|   - StreamID (4 байта, uint32)                              |
|   - FrameType (1 байт: DATA, OPEN, CLOSE, PING)             |
|   - PayloadLen (2 байта, uint16)                            |
|   - PaddingLen (2 байта, uint16: 16 - 256 байт)             |
|   - Полезная нагрузка (PayloadLen байт)                     |
|   - Случайный шум / Padding (PaddingLen байт)               |
|   - AEAD Tag (16 байт)                                      |
+-------------------------------------------------------------+
```
Благодаря случайному числу байт `Padding` длина пакетов в сети никогда не совпадает с реальными размерами HTTP/TCP пакетов, разрушая статистические модели классификации DPI.

### 3.5. Защита от активного зондирования (Active Probing Shield)
Если на сервер поступает подключение без валидного HMAC-токена в SessionID (сканер цензора, nmap, curl, обычный браузер):
- Сервер **не закрывает** соединение и **не выдает ошибок**.
- Сервер прозрачно связывает входящий сокет с реальным `FallbackTarget` (например, `www.microsoft.com:443`).
- Сканер цензора получает подлинное TLS 1.3 рукопожатие, валидный сертификат Microsoft Corporation и ответ HTTP 200/404.
- Цензор фиксирует, что сервер является обычным веб-сайтом/обратным прокси, и исключает его из подозрительных!
